## 1. Задача

Разработать приложение, иллюстрирующее работу четырех базовых алгоритмов растеризации:

1. Пошаговый алгоритм.
2. Алгоритм ЦДА.
3. Алгоритм Брезенхема для отрезков.
4. Алгоритм Брезенхема для окружности.

Приложение должно иметь графический интерфейс с возможностью масштабирования сетки, отображением
осей координат и выводом времени работы алгоритмов.

---

## 2. Реализация и Интерфейс

### Структура

Проект разделен на модули:

* `MainWindow` — управление интерфейсом (кнопки, поля ввода).
* `GridPanel` — компонент отрисовки. Отвечает за отображение координатной сетки, осей и пикселей.
  Поддерживает масштабирование и перемещение холста мышью.
* `Algorithms` — статический класс, содержащий математическую реализацию 4-х алгоритмов.

По поводу координатной плоскости:

* **Логические координаты:** Целые числа $(x, y)$, вводимые пользователем.
* **Экранные координаты:** Преобразуются по формуле:
  $$ ScreenX = CenterX + x \cdot CellSize $$
  $$ ScreenY = CenterY - y \cdot CellSize $$

## 3. Описание алгоритмов и примеры вычислений

Для демонстрации корректности выбран отрезок с координатами:
**Начало:** $(0, 0)$  
**Конец:** $(5, 2)$

В программе выводится Лог с шагами вычисления. И они полностью совпадают с моими ручными
вычислениями. \
Результаты вычислений можно посмотреть
в [Скриншотах работы программы](#5-скриншоты-работы-программы)

### 3.1. Пошаговый алгоритм

Основан на уравнении прямой $y = kx + b$.

* Вычисляется коэффициент наклона $k = \Delta y / \Delta x$.
* В цикле изменяется $x$, вычисляется $y$, результат округляется.

### 3.2. Алгоритм ЦДА (DDA)

Основан на вычислении приращений $\Delta x$ и $\Delta y$.

* Число шагов $L = \max(|\Delta x|, |\Delta y|)$.
* Приращение на шаг: $x_{inc} = \Delta x / L$, $y_{inc} = \Delta y / L$.
* Координаты хранятся в `double`, но потом округляются.

### 3.3. Алгоритм Брезенхема (Отрезок)

Полностью целочисленный алгоритм. Использует накопление ошибки.
**Пример вычисления $(0,0) \to (5,2)$:**

* $\Delta x = 5, \Delta y = 2$.
* Начальная ошибка: $E = 2\Delta y - \Delta x = 2(2) - 5 = -1$.

| Шаг (i) | Текущая точка (x, y) | Ошибка E (перед шагом) |            Действие             |      Новое E      |
|:-------:|:--------------------:|:----------------------:|:-------------------------------:|:-----------------:|
|    0    |      **(0, 0)**      |           -1           | $E < 0 \Rightarrow$ y не меняем |   $-1 + 4 = 3$    |
|    1    |      **(1, 0)**      |           3            |    $E \ge 0 \Rightarrow y++$    | $3 - 10 + 4 = -3$ |
|    2    |      **(2, 1)**      |           -3           | $E < 0 \Rightarrow$ y не меняем |   $-3 + 4 = 1$    |
|    3    |      **(3, 1)**      |           1            |    $E \ge 0 \Rightarrow y++$    | $1 - 10 + 4 = -5$ |
|    4    |      **(4, 2)**      |           -5           | $E < 0 \Rightarrow$ y не меняем |   $-5 + 4 = -1$   |
|    5    |      **(5, 2)**      |           -            |              Конец              |         -         |

### 3.4. Алгоритм Брезенхема (Окружность)

Использует симметрия окружности -- расчет идет только для 1/8 части, остальные точки отражаются.

* Начальная точка $(0, R)$.
* Начальная ошибка $E = 3 - 2R$.
* Используются только операции сложения, вычитания и сдвига (умножение на 4).

## 4. Временные характеристики

Измерение времени производилось с помощью `System.nanoTime()` на отрезке $(0,0) \to (100, 50)$ c
выключенными логами

| Алгоритм      | Время (мкс) |
|:--------------|:------------|
| **Пошаговый** | ~32         |
| **ЦДА**       | ~30         |
| **Брезенхем** | ~29         |

Результаты не самые "радужные" по причине того, что -- операция округления с помощью `Math.round` и всякие другие операции в Java не самые быстры.
Поэтому это может и сильно урезать скорость алгоритма. \
Также, прежде чем брать замеры, нужно провести несколько операций, чтобы программа "разогрелась".
